# Отчёт: shorty в Kubernetes

## Использованные абстракции

**Deployment** держит запущенным нужное число одинаковых подов и пересоздаёт упавшие.
- `api` — Go-бэкенд, 2 реплики, порт 8080
- `web` — фронтенд на nginx, 2 реплики, порт 80
- `postgres` — база данных, 1 реплика, порт 5432

**Job** — под, который выполняется один раз и завершается.
- `migrate` — создаёт таблицы в базе

**Service** даёт подам постоянное имя и распределяет запросы между ними.
- `api` — ClusterIP, доступен только внутри кластера
- `postgres` — ClusterIP, доступен только внутри кластера
- `web` — NodePort `30080`, доступен снаружи

**ConfigMap** `shorty-config` хранит обычные настройки: `BASE_URL`, `TOKEN_TTL`, `COOKIE_SECURE`.

**Secret** `shorty-secret` хранит пароли: доступ к PostgreSQL, `DATABASE_URL`, `JWT_SECRET`.

**PersistentVolumeClaim** `postgres-data` — диск на 1 Gi для данных PostgreSQL, переживает перезапуск пода.

## Взаимодействие сервисов

```
браузер → web → api → postgres ← migrate
```

- Браузер открывает `web`. nginx сам отдаёт страницу, а запросы к API пересылает на `api:8080`.
- `api` и `migrate` подключаются к базе по адресу `postgres:5432`.
- Имена `api` и `postgres` — это имена Service, внутри кластера они резолвятся через DNS.
