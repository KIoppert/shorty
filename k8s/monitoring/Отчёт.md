# Отчет: метрики shorty в VictoriaMetrics

## Стек

| Компонент | Технологии |
|---|---|
| Приложение | Go 1.27, `net/http`, PostgreSQL 17, nginx; запущено в minikube (namespace `shorty`) |
| Метрики приложения | `github.com/prometheus/client_golang` v1.25.0, формат Prometheus/OpenMetrics |
| Метрики PostgreSQL | `prometheuscommunity/postgres-exporter` v0.20.1, сайдкар в поде базы |
| TSDB | VictoriaMetrics single-node v1.154.0, Helm-чарт `vm/victoria-metrics-single`, namespace `monitoring` |
| Сбор | встроенный в VictoriaMetrics scraper (`server.scrape.enabled: true`), service discovery `kubernetes_sd_configs` по аннотациям `prometheus.io/*` |

## Файлы

| Файл | Что внутри |
|---|---|
| `api/metrics.go` | объявление метрик, обработчик `/metrics`, учет HTTP-запросов |
| `api/main.go` | отдельный HTTP-сервер для `/metrics` на порту `METRICS_PORT` (9091) |
| `api/auth.go`, `api/links.go` | увеличение бизнес-метрик в обработчиках |
| `k8s/40-api.yaml` | аннотации `prometheus.io/*` и порт `metrics` у пода `api` |
| `k8s/20-postgres.yaml` | сайдкар `postgres-exporter` и аннотации у пода `postgres` |
| `k8s/monitoring/vm-values.yaml` | values для Helm-чарта VictoriaMetrics |

## Установка VictoriaMetrics

Шаги 1 и 2 из инструкции VictoriaMetrics:

```bash
helm repo add vm https://victoriametrics.github.io/helm-charts/
helm repo update

helm install vm-single vm/victoria-metrics-single \
  -n monitoring --create-namespace \
  -f k8s/monitoring/vm-values.yaml
```

`vm-values.yaml` взят из примера к инструкции (`guide-vmsingle-values.yaml`): он включает сбор (`server.scrape.enabled: true`) и задачи для самой VictoriaMetrics, API-сервера, узлов и cadvisor. В пример добавлена задача `kubernetes-pods`, без нее поды по аннотациям не собираются:

- `kubernetes_sd_configs: role: pod` получает список подов из API Kubernetes, то есть таргеты определяются динамически (service discovery);
- `keep` по `prometheus.io/scrape: "true"` оставляет только поды, которые сами попросили их собирать;
- `prometheus.io/port` и `prometheus.io/path` задают адрес и путь;
- `keep_if_equal` по порту из аннотации и номеру порта контейнера оставляет у пода с несколькими портами только нужный. У `postgres` это 9187 экспортера, а не 5432 базы;
- метки пода, namespace, имя пода и контейнера добавляются к каждой метрике.

Чарт создает ServiceAccount и ClusterRole с правами на чтение подов, узлов и endpoints, поэтому discovery работает без ручной настройки RBAC.

Сбор выполняет сама VictoriaMetrics single, отдельный vmagent не нужен.

## Аннотации для service discovery

```yaml
# k8s/40-api.yaml
template:
  metadata:
    annotations:
      prometheus.io/scrape: "true"
      prometheus.io/port: "9091"
      prometheus.io/path: /metrics

# k8s/20-postgres.yaml
template:
  metadata:
    annotations:
      prometheus.io/scrape: "true"
      prometheus.io/port: "9187"
      prometheus.io/path: /metrics
```

После масштабирования `api` новые реплики попадают в сбор автоматически, ничего перенастраивать не нужно.

## Экспортеры

### Метрики рантайма Go (встроенный экспортер библиотеки)

`client_golang` по умолчанию регистрирует коллекторы рантайма Go и процесса. Их отдает обработчик `promhttp.Handler()`:

| Метрика | Что показывает |
|---|---|
| `go_goroutines` | число горутин |
| `go_threads` | число потоков ОС |
| `go_memstats_alloc_bytes` | занятая память кучи |
| `go_gc_duration_seconds` | длительность сборок мусора |
| `process_cpu_seconds_total` | потраченное процессорное время |
| `process_resident_memory_bytes` | резидентная память процесса |
| `process_open_fds` | открытые файловые дескрипторы |

`/metrics` работает на отдельном порту 9091. Service `api` и Ingress публикуют только порт 8080, поэтому метрики доступны без авторизации, но только изнутри кластера, по IP пода.

### Метрики HTTP

| Метрика | Тип | Метки |
|---|---|---|
| `shorty_http_requests_total` | counter | `route`, `method`, `status` |
| `shorty_http_request_duration_seconds` | histogram | `route`, `method` |

`route` берется из шаблона маршрута (`GET /api/links/{id}`, `GET /{code}`), а не из реального пути. Поэтому каждая короткая ссылка не создает отдельный ряд, и число рядов не растет вместе с числом ссылок.

### Метрики PostgreSQL (postgres-exporter)

Экспортер запущен вторым контейнером в поде `postgres-0`. Контейнеры пода делят сеть, поэтому он подключается к базе по `localhost:5432`, логин и пароль берет из `db-secret`.

| Метрика | Что показывает |
|---|---|
| `pg_up` | доступна ли база (1 или 0) |
| `pg_stat_database_numbackends` | активные подключения |
| `pg_stat_database_xact_commit` | число завершенных транзакций |
| `pg_stat_database_tup_inserted`, `pg_stat_database_tup_fetched` | вставленные и прочитанные строки |
| `pg_database_size_bytes` | размер базы |
| `pg_settings_max_connections` | лимит подключений |

## Бизнес-метрики

| Метрика | Тип | Метки | Что считает |
|---|---|---|---|
| `shorty_users_registered_total` | counter | | успешные регистрации |
| `shorty_logins_total` | counter | `result`: `success`, `failure`, `banned` | попытки входа по результату |
| `shorty_links_created_total` | counter | `type`: `custom`, `random` | созданные ссылки: со своим алиасом или со случайным кодом |
| `shorty_redirects_total` | counter | `result`: `ok`, `not_found`, `gone` | переходы по коротким ссылкам: успешные, на несуществующий код, на выключенную или истекшую ссылку |
| `shorty_qr_codes_generated_total` | counter | | сгенерированные QR-коды |

Все значения меток создаются при старте с нулем, чтобы ряды существовали до первого события. Счетчики живут в каждой реплике отдельно, поэтому в запросах они суммируются через `sum`.

## Проверка сбора

```bash
kubectl get pods -n monitoring
kubectl get pods -n shorty
kubectl port-forward svc/vm-single-victoria-metrics-single-server -n monitoring 8428:8428
```

Запросы выполнялись в vmui (`http://localhost:8428/vmui`) после действий в интерфейсе приложения:

| Запрос | Что проверяет |
|---|---|
| `up` | все таргеты найдены по аннотациям и отвечают: обе реплики `api` (порт 9091) и `postgres-exporter` (порт 9187) |
| `pg_up` | экспортер подключен к PostgreSQL |
| `sum(shorty_users_registered_total)` | регистрации |
| `sum by (result) (shorty_logins_total)` | входы: успешные и с неверным паролем |
| `sum by (type) (shorty_links_created_total)` | ссылки со случайным кодом и со своим алиасом |
| `sum(shorty_qr_codes_generated_total)` | открытые и скачанные QR-коды |
| `sum by (result) (shorty_redirects_total)` | переходы: успешные, на несуществующий код, на выключенную ссылку |

Все таргеты в состоянии `up = 1`, `pg_up = 1`, бизнес-метрики растут после соответствующих действий в интерфейсе.
